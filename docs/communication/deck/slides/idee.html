Voici l’idée qui répond au premier problème, celui du contexte. Plutôt que de laisser le modèle appeler chaque outil lui-même et relire chaque réponse, on lui demande d’écrire un petit programme. Le modèle dit ce qu’il veut, l’intention. Le code fait les appels intermédiaires, filtre, agrège, et ne rend au modèle qu’un résultat borné, c’est-à-dire de taille limitée. Tout ce qui se passe entre les deux ne traverse jamais le contexte du modèle. Pour cela, le modèle ne voit que trois outils, qu’on appelle des méta-tools. search pour chercher un outil dans le catalogue. describe pour lire ce qu’un outil attend et ce qu’il rend. execute pour lancer le script qui fait le travail. C’est l’objectif unique de cette version : réduire le contexte et les tokens consommés par tâche, avec un seul chemin d’exécution pour le produit, le développement et la CI. Le gain se mesurera sur les mêmes tâches, avant et après ; la date de cette mesure de référence reste à fixer par le propriétaire.
