Si vous ne retenez qu’une chose pratique, c’est celle-ci. La brique de base tient en une commande : srt, tiret tiret settings, builder.json, claude. Elle lance votre Claude Code habituel, mais à l’intérieur d’un sandbox, dans votre worktree habituel. Le fichier builder.json, placé hors de tout chemin inscriptible, dit ce qui est permis. Écrire : le worktree, et les parties de git nécessaires à un commit. Refusé : les hooks git, la configuration git commune, les fichiers de réglages Claude Code du worktree, parce qu’un réglage de projet pourrait désactiver les hooks de protection en cours de session. Illisibles : ~/.ssh, ~/.aws, ~/.gnupg et les autres dossiers d’identifiants. Réseau : Anthropic, npm et GitHub, rien d’autre. Les risques qui restent sont écrits, R-1 et R-2, par exemple le trousseau qui reste lisible. C’est aussi le stage 0 : le reste de la plateforme se construit à l’intérieur de cet outil. Ce qui est vérifié : sur le poste macOS, la commande fonctionne en mode non interactif avec le compte Claude, sur un appel réel minimal. Ce qui reste à prouver : l’interface interactive, la TUI, au premier lancement. Une première version du profil avait d’ailleurs permis une évasion, prouvée en réécrivant un pointeur de worktree ; c’est ce qui a conduit aux refus que vous voyez ici.
